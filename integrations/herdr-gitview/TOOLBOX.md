# Gitview в herdr-toolbox

Полная копия [ChmaraX/herdr-gitview](https://github.com/ChmaraX/herdr-gitview) версии 0.6.0,
[коммит f69e71b](https://github.com/ChmaraX/herdr-gitview/tree/f69e71bbbb53237c27d8282c1d4a95d11380daf1).
Оригинальный [LICENSE](LICENSE) содержит лицензию MIT и уведомление об авторских правах Adam Chmara.
В каталоге сохранены исходники интерфейса, Rust-бинарника, установщиков и тестов. Сборки и локальные настройки
Herdr сюда не копируются. Проверки и сборка настроены в корне `herdr-toolbox`; файлы публикации релизов
оригинального проекта не используются. При обновлении сравнивай с указанным коммитом.

Сборка заменяет установленный Gitview, а не работает рядом с ним. Имена модов, настройки и клавиши Cmd+G /
Cmd+Shift+G сохранены. Установщик `herdr-app/install.sh` также обновляет раскладку и клавиши; перед рабочей
установкой сохрани текущие моды, конфигурацию и раскладки Herdr. Для проверки сначала используй отдельный
каталог установки. Мод `snippets` по-прежнему может найти бинарник через `mods/gitview/config.json`.

## Проверки и установка

[CI в herdr-toolbox](https://github.com/AndronovVladislav/herdr-toolbox/actions/workflows/ci.yml) запускается для
запросов на слияние в `master`, после изменений в `master` и вручную. В успешном запуске доступны архивы
`gitview-aarch64-apple-darwin` и `gitview-x86_64-unknown-linux-gnu`. Для доступа к ним нужен доступ
к репозиторию. Релизы не публикуются автоматически.

- Из исходников, с установленным Rust и открытым Herdr: `./install.sh`.
- Из CI: распакуй скачанный артефакт GitHub, оставь `.tar.gz` рядом с `.tar.gz.sha256` и запусти
  `./install.sh --bundle /path/to/herdr-gitview-app-TARGET.tar.gz` из нашей копии Gitview.
- Без рабочей копии: проверь архив командой `shasum -a 256 -c FILE.tar.gz.sha256` или
  `sha256sum -c FILE.tar.gz.sha256`. Распакуй архив Gitview и запусти `./install.sh` из распакованного каталога.

Установщик не скачивает релизы оригинального проекта. Архив содержит `LICENSE` и этот документ.

## Сравнение в две колонки

В панели diff нажми `b` или кнопку `Unified` в заголовке. Слева появится старая версия,
справа — новая; у строк без пары соседняя ячейка останется пустой. Повторное нажатие
вернёт обычный diff. Выбор действует в этой панели при переходе между файлами.

Щёлкни по нужной стороне, чтобы переместить курсор. `j`/`k` перемещают его по строкам
сравнения, `h`/`l` прокручивают обе колонки горизонтально. Выделение и заметка относятся
к стороне, с которой начато выделение. Переключение раскладки не меняет базу сравнения,
индекс или файлы.

## Открытие файла в графическом редакторе

Клавиша `o` открывает корень локального репозитория или worktree и выбранный файл,
не закрывая diff.
Чтобы выбрать редактор независимо от того, как запущен Herdr, добавь в начало
`~/.config/herdr/plugins/config/chmarax.gitview/config.toml` (или в `config.toml` внутри
`GITVIEW_CONFIG_DIR`, если он задан):

```toml
visual_editor = ["/Applications/Zed.app/Contents/MacOS/cli"]
```

Если список файлов пуст, `o` открывает только корень текущего worktree. Если выбран файл, Gitview передаёт редактору корень и путь к файлу двумя аргументами. Если `visual_editor`
не задан, используется `VISUAL` из окружения Herdr. Без обеих настроек откроется только
папка проекта через `open` на macOS или `xdg-open` на Linux. Настройка
влияет только на `o`; для файлов на удалённой машине используй `Enter`.

## Редактирование заметок

В diff нажми кнопку с карандашом на карточке заметки. Чтобы изменить привязку, щёлкни
по нужной строке или выдели диапазон мышью прямо во время редактирования. Можно также
выделить диапазон до нажатия карандаша. `Enter` сохраняет заметку, `Esc` отменяет правки.

## Как Gitview выбирает рабочую копию

1. Панель Changes следует за терминалом в фокусе. При переходе в diff или диалог **той же вкладки** она
   сохраняет терминал-источник, но продолжает читать его актуальную метку. Если источника ещё нет и во вкладке
   несколько подходящих терминалов, Gitview просит выбрать терминал.
2. Cmd+G привязывает отдельную вкладку Gitview к терминалу, из которого его вызвали. Перейти к другому агенту
   можно вызовом Cmd+G из его терминала. Если исходный терминал остановлен, вкладка не переключается молча
   на другую копию.
3. Для выбранного терминала приоритет такой: **закреплённый путь → путь, сообщённый агентом → каталог терминала**.
   Если терминала нет, Gitview может показать каталог пространства. Источник и путь видны над списком файлов.
   Указанная вручную или агентом рабочая копия обязана существовать и быть корнем Git на машине этого терминала.
   Ошибка не приводит к подстановке другой копии.
4. При переключении Gitview обновляет список и diff. Запоздавшие ответы загрузки не подменяют новый список.
   Команды изменения файлов и индекса получают точные машину и корень; перед записью мод сверяет метку с Herdr,
   а бинарник проверяет, что целевой каталог всё ещё является корнем Git. Если метка поменялась до проверки,
   действие отменяется. Начавшаяся команда не переносится в другую копию.

У Gitview нет способа надёжно увидеть каталог каждого вызова инструмента агента. Агент должен сообщить
о переходе **после проверки каталога и ветки, до начала работы** и очистить метку при возврате:

```sh
hc label "$HC_TERMINAL_ID" "gitview.worktree=/absolute/path/to/worktree"
hc label "$HC_TERMINAL_ID" gitview.worktree=
```

### Pi: переключение Gitview после `/move`

Для Pi 1.5.2 с `pi-session-move` установи расширение отдельно от Gitview. Из этого каталога выполни:

```sh
pi_dir="${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}"
mkdir -p "$pi_dir/extensions"
cp pi/gitview-worktree.js "$pi_dir/extensions/"
```

В открытом Pi один раз выполни `/reload`. Теперь при запуске Pi и после успешного `/move` Gitview получает
корень Git из каталога открытой сессии, даже если Pi перешёл в подпапку. Если переход отменён, метка не меняется.
При переходе вне репозитория расширение очищает метку, и Gitview возвращается к каталогу терминала.
Расширение не меняет закреплённый путь и не отслеживает смену каталога отдельными командами агента.

### Ручное закрепление

Чтобы закрепить копию независимо от меток агента, выполни команды для нужного терминала Herdr:

```sh
hc label "$TERMINAL" "gitview.pinnedWorktree=/absolute/path/to/worktree"
hc label "$TERMINAL" gitview.pinnedWorktree=
```

Подставь адрес нужного терминала вместо `$TERMINAL`. Для удалённого терминала используй полный адрес (например, `machine/t7`) и путь на его машине.
Закрепление действует на этот терминал; чтобы вернуться к слежению за агентом, очисти закреплённый путь.
